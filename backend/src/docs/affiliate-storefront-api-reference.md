# Affiliate Storefront API Reference

This document is for connecting a trusted ecommerce/storefront backend to the
Affiliate Management API. Make these calls only from the storefront server;
never expose any secret in browser or mobile-client code.

## Environment configuration

Configure the affiliate service:

```env
STOREFRONT_API_KEY=<unique-random-secret-at-least-32-characters>
RAZORPAY_WEBHOOK_SECRET=<razorpay-webhook-secret>
```

Configure the same shared key in the storefront backend:

```env
AFFILIATE_API_URL=https://<affiliate-api-domain>
STOREFRONT_API_KEY=<the-exact-same-secret>
```

If the affiliate service uses `API_PREFIX`, append it to every route below.
For example, when `API_PREFIX=/api/v1`, the conversion URL becomes
`https://<affiliate-api-domain>/api/v1/referrals/conversion`.

## Authentication

### Storefront API calls

Use the shared API key in this HTTP header:

```http
X-Storefront-Api-Key: <STOREFRONT_API_KEY>
```

The affiliate API compares the value securely and returns `401 Unauthorized`
for a missing or invalid key.

### Razorpay webhook calls

Razorpay sends the webhook signature in this header:

```http
X-Razorpay-Signature: <HMAC-SHA256 signature>
```

The signature is an HMAC-SHA256 of the raw request body, using
`RAZORPAY_WEBHOOK_SECRET`. Do not parse or change the request body before
signature verification.

## 1. Validate the referral coupon before checkout

Use this server-to-server call before calculating the order total.

```http
GET https://<affiliate-api-domain>/referrals/coupon-status/AFF-123?customerEmail=buyer%40example.com
X-Storefront-Api-Key: <STOREFRONT_API_KEY>
```

Apply the affiliate discount only when the response's `data.valid` and
`data.eligible` are both `true`. Persist the validated referral code, click ID,
discount percent, and discount amount on the immutable order record.

## 2. Record a paid conversion

Call this only after payment has been confirmed by your payment gateway or a
trusted gateway webhook.

```http
POST https://<affiliate-api-domain>/referrals/conversion
Content-Type: application/json
X-Storefront-Api-Key: <STOREFRONT_API_KEY>
```

### Request body

```json
{
  "referralCode": "AFF-123",
  "clickId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "orderId": "your-immutable-order-id",
  "customerEmail": "buyer@example.com",
  "grossAmount": 2000,
  "discountAmount": 200,
  "eligibleAmount": 1800,
  "amount": 1800,
  "currency": "INR"
}
```

### Field requirements

| Field | Required | Rules |
| --- | --- | --- |
| `referralCode` | Yes | Valid active affiliate referral code; maximum 50 characters. |
| `clickId` | Yes | UUID generated by `GET /referrals/click/:code`; it must match the referral code. |
| `orderId` | Yes | Your immutable internal order ID; maximum 100 characters. |
| `customerEmail` | Yes | Valid customer email; used for one-time coupon eligibility. |
| `amount` | Yes | Final paid amount, greater than zero. |
| `grossAmount` | No | Order amount before affiliate discount. |
| `discountAmount` | No | Affiliate discount amount. |
| `eligibleAmount` | No | Amount eligible for commission calculation; normally final paid amount. |
| `currency` | No | Three-letter currency code; defaults to `INR`. |

`orderId` is idempotent. Retrying the same paid order returns the existing
conversion and does not create another commission. Mark the storefront order
as synced only after a successful API response; retry failed sync attempts from
a backend worker.

### Node.js example

```js
const response = await fetch(
  `${process.env.AFFILIATE_API_URL}/referrals/conversion`,
  {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-Storefront-Api-Key': process.env.STOREFRONT_API_KEY,
    },
    body: JSON.stringify({
      referralCode: order.referralCode,
      clickId: order.clickId,
      orderId: String(order._id),
      customerEmail: order.customer.email,
      grossAmount: order.subtotal,
      discountAmount: order.affiliateDiscount,
      eligibleAmount: order.finalPaidAmount,
      amount: order.finalPaidAmount,
      currency: order.currency || 'INR',
    }),
  }
);

if (!response.ok) throw new Error(`Affiliate conversion failed: ${response.status}`);
```

## 3. Refund and commission reversal

There is currently no separate public refund/reversal REST endpoint. Refund
reversal is handled by the built-in Razorpay webhook integration.

### Webhook endpoint

```http
POST https://<affiliate-api-domain>/payments/webhook
X-Razorpay-Signature: <HMAC-SHA256 signature>
```

Configure this URL in the Razorpay dashboard and configure the identical
`RAZORPAY_WEBHOOK_SECRET` in the affiliate API environment. If `API_PREFIX` is
configured, use `<API_PREFIX>/payments/webhook` instead.

Supported payment events are:

```text
payment.authorized
payment.captured
order.paid
payment.failed
refund.created
refund.processed
```

Only `refund.processed` triggers the automated reversal workflow. A typical
Razorpay payload shape is:

```json
{
  "event_id": "event_xxx",
  "event": "refund.processed",
  "payload": {
    "refund": {
      "entity": {
        "id": "rfnd_xxx",
        "payment_id": "pay_xxx",
        "order_id": "order_xxx",
        "amount": 180000
      }
    }
  }
}
```

`amount` in Razorpay webhook payloads is in paise: `180000` means INR 1,800.
The service records webhook event IDs, so duplicate Razorpay deliveries are
safe.

### Reversal behaviour

- A full processed refund changes the payment and conversion to refunded.
- Pending and approved commissions are rejected.
- If a commission was already approved, its amount is debited from the
  affiliate wallet and an auditable `COMMISSION_REVERSAL` wallet transaction is
  created.
- A partial refund is stored as `PARTIALLY_REFUNDED`; a proportional commission
  reversal policy is not implemented yet.

## Security checklist

- Keep `STOREFRONT_API_KEY`, `RAZORPAY_WEBHOOK_SECRET`, database credentials,
  and gateway keys in server environment variables only.
- Never call coupon-validation or conversion endpoints directly from React,
  browser JavaScript, or a mobile client.
- Calculate all order values from trusted server-side product, cart, and order
  data.
- Do not submit conversions for unpaid, cancelled, or already refunded orders.
